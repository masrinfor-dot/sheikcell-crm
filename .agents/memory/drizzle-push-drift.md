---
name: Schema change path
description: How to ship DB schema changes — drizzle push is broken by drift; migrations/*.sql are discovered by directory
---
`pnpm run push` in `lib/db` aborts on pre-existing drift (dev DB `bot_usage` lacks `tenant_id`), so drizzle-kit cannot apply anything until fixed. **The sanctioned path:** add an idempotent SQL file to `migrations/` (numbered, zero-padded prefix) plus the matching drizzle schema file. The api-server boot runner (`lib/migrate.ts`, `runMigrations`) **discovers every `migrations/*.sql` by reading the directory** (sorted by name) — there is NO list to register the file in anymore (the old hardcoded `MIGRATION_FILES` array was removed after the 11/09 outage caused by a migration that was created but never added to it). **Why:** a dev-only manual `psql` change works locally but leaves prod without the table; the directory scan is the only mechanism that also creates the schema on deployed/fresh databases. **How to apply:** every new table/column ships as a numbered idempotent migration (`IF NOT EXISTS` / `DO $$` guards — it re-runs on every boot) + matching drizzle schema change; nothing else to wire. For a throwaway local Postgres (tests), `DATABASE_URL=... pnpm --filter @workspace/db run push-force` creates the whole schema from drizzle in one go.
